# Закрытый доступ 777XSZ Academy — инструкция по развёртыванию

**Статус:** серверный прототип создан в рабочей ветке `777xsz-academy`. Не развёрнут и не прошёл нагрузочный/пентест-аудит. Публичный сайт не изменён.

## Модель доступа
- Ученик регистрируется с индивидуальным email и паролем (минимум 12 символов).
- Новый аккаунт получает `approved=0` и не может читать курсы.
- Администратор создаётся **только через CLI** и подтверждает/отзывает доступ каждому ученику отдельно.
- Пароли хранятся в виде хешей PHP `password_hash`; сессии используют HttpOnly, Secure и SameSite.
- Чтение каждого курса проходит серверную проверку одобрения.
- Курс хранится в частной директории вне webroot; ссылка на урок без авторизации не раскрывает файл.

## Развёртывание (нужен PHP 8.1+, PDO SQLite, HTTPS, CLI и доступ к переменным окружения)
1. Создать на хостинге две **раздельные** директории:
   - публичную `public_html/academy/` для `index.php`;
   - приватную, **вне public_html**, например `/home/USER/academy-data/courses/`.
2. Скопировать `academy-private/index.php` в публичную директорию академии.
3. Скопировать 25 HTML-курсов **только** в `academy-data/courses/<slug>/index.html`.
4. Установить переменную окружения `ACADEMY_DATA_DIR=/home/USER/academy-data`. Каталог должен быть доступен на запись процессу PHP для SQLite.
5. Включить HTTPS и закрыть доступ к приватному каталогу на уровне сервера/файловой системы.
6. Создать первого администратора через CLI: `php index.php create-admin admin@example.com`. Использовать собственный email и уникальный длинный пароль.
7. Проверить регистрацию, отказ неутверждённому пользователю, одобрение, чтение, отзыв доступа, выход и повторный вход.
8. Только после проверки удалить публичные копии защищённых HTML-курсов из **каждого публичного источника публикации**, включая GitHub Pages. Не публиковать закрытые страницы в статическом репозитории, CDN или sitemap.

## Блокирующие вопросы до реального запуска
- Выяснить, поддерживает ли текущий хостинг PHP 8.1+, PDO SQLite, CLI, переменные окружения и приватную директорию.
- Настроить корректные ссылки внутри существующих HTML-курсов: ссылки вида `/courses/...` пока ведут на публичные URL, а не в защищённый reader. Нужна адаптация шаблонов и навигации.
- Проверить, что все используемые CSS, шрифты, изображения и JS доступны без публикации самих текстов уроков.
- Добавить безопасное восстановление пароля, подтверждение email и защиту регистрации от автоматизированного спама.
- Добавить ограничение попыток входа не только по IP, но и по аккаунту; продумать доверенные прокси и журналы безопасности без секретов.
- Провести аудит сессий, CSRF, XSS, rate limiting, прав администратора и резервных копий.
- Уточнить требования к персональным данным учеников, сроки хранения и уведомления.
- Протестировать доступ с телефона и компьютера и выполнить негативные сценарии (неодобренный пользователь, прямой URL, отозванный доступ).

**Не делайте вид, что клиентская авторизация защищает публичный HTML.** Без переноса файлов на защищённый сервер закрытая академия не существует.
