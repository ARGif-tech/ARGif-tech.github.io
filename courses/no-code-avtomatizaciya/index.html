Выбор процесса

Выберите один повторяющийся процесс с понятным входом и выходом.

Практика

Нарисуйте цепочку из трёх действий.

Практический проект: обработка новой заявки

Учебная цель: после поступления заявки с сайта проверить обязательные поля, добавить запись в таблицу и уведомить ответственного менеджера. Начинайте с этого простого процесса, а не с автоматического общения с клиентом.

Опишите входные данные: идентификатор заявки, время, тип услуги, район, предпочтительный способ связи. Для упражнений используйте вымышленные данные. Выход: одна корректная запись и уведомление без лишней личной информации.

Критерий готовности: вы можете объяснить процесс как «получить → проверить → сохранить → уведомить» без названий конкретных сервисов.

Событие и действие

Разделите триггер, условия, действие и исключения.

Практика

Опишите автоматизацию новой заявки.

Логика сценария без программирования

  1. Триггер: получена новая тестовая заявка.
  2. Проверка: есть тип услуги и согласованный канал обратной связи.
  3. Защита от дублей: идентификатор ещё не встречался.
  4. Действие: сохранить запись в тестовой таблице.
  5. Уведомление: отправить ответственному сообщение о новой заявке.
  6. Исключение: если проверка не пройдена, пометить заявку для ручного разбора.

Не отправляйте клиенту автоматически цену или обещание сроков. Эти решения требуют проверенных правил и отдельного согласования.

Выбор платформы

Сравните доступные тарифы, интеграции, экспорт данных и ограничения официальных платформ.

Практика

Составьте таблицу выбора без выдуманных цен.

Таблица выбора инструмента

Сравните платформы по пяти критериям: поддержка нужного источника заявки, стоимость при вашем объёме, доступность экспорта, история ошибок, возможность отключить сценарий. Проверьте официальную документацию и тарифы на дату выбора.

Для ориентира изучите Make, Zapier и n8n. Это примеры разных подходов, а не обещание бесплатного или одинакового набора функций. Самостоятельный хостинг также требует обслуживания и защиты.

Практика: заполните матрицу выбора из трёх платформ и объясните выбор одним абзацем.

Тестовые данные

Используйте только синтетические заявки и отдельный тестовый сценарий.

Практика

Создайте пять тестовых записей.

Пять тестовых заявок

  1. Корректная заявка: услуга «уборка», район «Центр», контакт «test1@example.invalid».
  2. Нет типа услуги.
  3. Повтор заявки с тем же идентификатором.
  4. Контакт отсутствует, но есть запрос на обратную связь.
  5. Неожиданно длинное поле с лишними символами.

Ожидаемые результаты: первая сохраняется; вторая и четвёртая уходят на ручную проверку; третья не создаёт дубль; пятая безопасно отклоняется либо ограничивается по установленным правилам. Используйте домен .invalid, чтобы тестовые письма не отправлялись реальным людям.

Обработка ошибок

Добавьте проверку дублей, неудачных запросов и ручное подтверждение рискованных действий.

Практика

Пропишите три пути отказа.

Три обязательных сценария ошибки

Источник прислал дубль: проверка идентификатора предотвращает повторную запись. Таблица недоступна: фиксируйте сбой без токенов и персональных данных в журнале; повторяйте действие только по безопасному правилу. Уведомление не отправилось: сохранённая заявка остаётся в очереди ручной обработки.

Особенно опасны повторные операции с оплатой, рассылками и изменением статуса заказа. Для них нужны подтверждение человека, защита от повторного выполнения и отдельные тесты.

Практика: для каждой ошибки запишите: как обнаружить, что делать, кто получает сигнал и как восстановить работу.

Запуск под контролем

Проверьте журнал событий, возможность отключения и отсутствие утечек.

Практика

Проведите пять тестов и сохраните результаты.

Приёмочные испытания

  • Корректная заявка создаёт ровно одну запись.
  • Повторная заявка не создаёт дубль.
  • Отсутствующее обязательное поле не приводит к ложному подтверждению.
  • Недоступность внешнего сервиса фиксируется и не теряет заявку бесследно.
  • Выключение сценария действительно останавливает дальнейшие действия.

Запишите результаты испытаний в таблицу «тест → ожидаемое → фактическое → исправление». После тестов отдельно проверьте права доступа, секреты в настройках и срок хранения данных. Переход к реальным клиентским данным допускается только после проверки требований конфиденциальности и разрешений.

Итоговый практический проект

Автоматизация обработки заявки

На тестовых данных соедините событие, проверку полей, запись в таблицу и уведомление. Проверьте повторную и пустую заявку.

Проверка результата

Пустая заявка отмечается, дубликат не создаётся, ошибки видны ответственному.

Для портфолио: сохраните результат, краткое описание задачи, выполненные шаги и обнаруженные ошибки. Не публикуйте чужие материалы или персональные данные без разрешения.

Повторите упражнение на собственном примере. Курс бесплатный, покупать услуги автора не требуется.
